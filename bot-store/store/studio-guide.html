Studio / evaluation 0.5

Run your own monitor.

Requires Node.js 20 or newer. Tested with Node.js 22 on Linux. Windows and macOS have not been independently tested.

Download Sentinel Studio

1. Start the application

Save the file in a dedicated folder. Open a terminal in that folder and run:

node --version
node sentinel-studio.mjs

Open http://127.0.0.1:4317/ in a browser on the same computer. Keep the terminal running. Do not expose this application to the internet or other users.

2. Add your first endpoint

Enter a name, HTTP(S) URL without credentials or query parameters, a check interval of at least 60 seconds and expected HTTP status. Use endpoints you own or have permission to monitor. Click Add endpoint, then Check to perform an on-demand test. Edit an endpoint with its Edit button and Save changes, or Cancel edit to discard changes. Search by name or URL and filter by health. Changing the URL or expected status resets the current health and closes any existing incident as Configuration changed, not Recovered. Select Start monitoring to begin scheduled checks.

3. Understand the results

Checks follow redirects and compare final HTTP status. The latency measures the HTTP response check, not page rendering. An incident opens on failure and closes when the expected status returns. Repeated failures do not create duplicate open incidents. Filter incident history by open or resolved status. On narrow screens, records stack vertically with field labels.

4. Keep and export records

State is saved in sentinel-data/state.json relative to the folder you launch from. Use Export JSON to obtain a snapshot. Keep backups and run only one instance per data folder. Up to 3,000 checks and 500 resolved incidents are retained. Open incidents are retained. Stop with Ctrl+C; restart monitoring manually when you launch again. Pausing prevents future scheduled batches; a batch already in progress may finish.

Windows x64 setup

See the Windows evaluation installation guide for an optional per-user setup and startup task. Direct Windows execution remains unverified.

5. Configure notifications (optional)

Set these environment variables privately on your own computer before launching Studio. Never share credentials or commit them to source control.

  • Discord: SENTINEL_DISCORD_WEBHOOK (HTTPS discord.com webhook URL).
  • Telegram: SENTINEL_TELEGRAM_TOKEN and SENTINEL_TELEGRAM_CHAT (bot token and authorized chat ID).
  • Email: SENTINEL_RESEND_KEY, SENTINEL_EMAIL_FROM, SENTINEL_EMAIL_TO (Resend account and verified sending identity required).

Open Notifications, choose a consecutive failure threshold (1–20 checks) and reminder cooldown (60–86400 seconds), set recovery alerts, enable alerts and save. Alerts are disabled by default. Send test attempts delivery to every configured channel, including when automatic alerts are disabled. This sends real messages if real credentials are configured. Alert payloads include endpoint names, not URLs; avoid sensitive names.

Delivery records distinguish accepted, failed and interrupted attempts. HTTP acceptance does not prove inbox delivery. Failed attempts are not automatically retried; a subsequent failing check after cooldown can trigger a reminder. Credentials are not included in saved state or exports. The monitoring batch may take longer while notifications are sent.

Evaluation limitations

This is an experimental, local-only evaluation, not a hosted service. No signed installer, browser-content assertions, commercial license or service guarantee. 21 API checks, 17 notification fixture checks, 10 browser interaction harness checks and 4 restart preference checks passed. Live messaging providers have not yet been independently verified. The harness loads the real dashboard HTML and JavaScript in Chromium and bridges requests to the local server. Direct browser navigation is blocked in the test environment; installation and end-to-end transport remain unverified. This is not a commercial release.
