01 / What it does

Keep the changes that matter.

Source library

Monitor public text or JSON, including individual fields. Inspect last attempt, last successful capture, stale status, estimated next eligible check and retained rule-match history.

Relevant signals

Literal keyword appearance or disappearance and numeric threshold crossings. Nonmatching changes remain recorded.

Evidence inbox

A focused evidence reader with a compact index, pinned selection, source-specific filters, saved bookmarks and local investigation notes.

External delivery

Opt in to Discord, Telegram or Resend email. Persistent ledger distinguishes accepted, failed, uncertain and skipped attempts.

02 / First run

From download to first result.

  1. Install Node.js 22 or newer.

    Official Node.js download. No Bot.AutoHustle account required.

  2. Extract the complete ZIP.

    Keep all application modules together in a dedicated folder.

    Download evaluation ZIP ↓
  3. Launch the local application.

    Open a terminal in the extracted folder.

    node studio.mjs

    Open http://127.0.0.1:4321/ on the same computer.

  4. Add your first public source.

    Open Source library, choose text or JSON, optionally select a field and rule, check to establish a baseline, then start monitoring. Open Evidence inbox to review captured changes.

Before you run

Automatic monitoring and external alerts start disabled after restart. Configure your own notification credentials locally.

Data is unencrypted. Only monitor authorized, nonsensitive sources.

Keep the terminal open while monitoring. Ctrl+C stops the process. Do not expose the local dashboard to the internet.

03 / Technical truth

Precise rules, explicit limits.

118 local checks passed for Studio 0.7: 50 Node tests, 46 HTTP integration checks and 22 workspace checks. The browser harness uses the actual application HTML and scripts with bridged local API requests. Direct browser navigation, live provider receipts and Windows acceptance remain outstanding.
Source and comparison limits

1–20 sources, 300–86400 second intervals, 512 KiB response cap, 10-second request timeout. Direct HTTP(S) URLs without credentials, queries, fragments or redirects. Complete line comparisons for up to 8,192 combined characters and 120 lines each; larger inputs show excerpts. HTML is raw text, not rendered. Rules are deterministic, not semantic AI.

Delivery and restart behavior

Only matching changes from opted-in sources are queued when global alerts are enabled. Credentials stay in the local environment. HTTP acceptance is not a receipt. Failed or uncertain delivery is not automatically retried; restart skips pending delivery. Full notification setup.

Configuration, evidence and review notes

Imports merge missing sources without overwriting existing ones. Credentials, history and delivery opt-ins are excluded. Retains 200 inbox events and up to 500 delivery records. Explicitly protected copies (up to 100) survive inbox eviction, include saved notes and can be exported separately. Bookmarks alone do not prevent eviction. A full archive refuses new copies. Evidence is unencrypted, editable local data, not an immutable audit ledger. Last successful capture is recorded from 0.6 onward. Retained event counts exclude unchanged checks and are not uptime or rule accuracy.

Runtime integrity

The current runtime is assembled from tested, version-matched source files. The previous 0.4 SHA-256 checksums apply only to that older release. Website ZIP contains runtime and documentation, not developer tests. No signed release or commercial checkout.

Execution architecture / 0.7

Capture independently. Preserve what matters.

Four capture slots

Up to four source captures run concurrently within one batch. Completed results commit individually; edited or removed sources invalidate outdated results.

Independent delivery

Notification requests do not block capture transactions. One delivery attempt runs at a time. Disabling alerts skips queued work, not requests already sent.

Protected evidence

Save up to 100 explicit copies independently of the 200-event inbox. Export saved evidence and notes; no automatic archive eviction.

State integrity

Serialized state updates, synchronized temporary files and atomic replacement. Startup rejects malformed records and snapshot digest mismatches without overwriting the original. Backups remain necessary.

One capture batch at a time; pause stops queued scheduled captures but in-flight results may finish. Manual batches retain their existing UI pending state. No directory fsync or full power-loss guarantee. Windows, live providers and external-source operations remain unverified.
