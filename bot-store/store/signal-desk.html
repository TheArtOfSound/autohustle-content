01 / Practical monitoring

Follow the information, not just the page.

Public release changes

Watch a version field in a public JSON manifest instead of comparing its entire response.

Text updates

Capture changes to approved text sources, with normalized line endings and trailing whitespace.

Evidence first

Record the first differing character and bounded before/after excerpts. Failures never replace the last good baseline.

02 / Studio workspace

Review changes in one place.

Source library

Add, edit and remove sources without editing JSON files. Check immediately or run the scheduler.

Evidence inbox

Search and filter by relevance. Matching changes can become unread; non-matches remain in the evidence feed.

Persistent review

Retain source settings and review state, even after restart. Export the evidence record as JSON.

Choose what deserves attention

Keyword transitions

Detect when a literal keyword appears or disappears. Optional case sensitivity.

Numeric crossings

Watch a finite JSON number cross strictly above or below a threshold. Invalid readings preserve the last good baseline.

Complete line comparison

Review added, removed and unchanged lines when combined snapshots are at most 8,192 characters and each has at most 120 lines. Larger inputs show bounded excerpts.

Changing a rule starts a new baseline. Nonmatching changes remain recorded as read. Rules are deterministic, not semantic AI classification. Exports can include complete contents of small documents; avoid sensitive sources.

Deliver relevant signals

Discord, Telegram and email

Configure your own credentials locally. Enable external alerts globally and per source. Only matching changes are queued.

Delivery ledger

Review accepted, failed, uncertain and skipped attempts. No automatic retry for uncertain delivery.

Organized sources

Group sources and merge reusable configuration without importing credentials, evidence or delivery permissions.

Automatic external alerts start disabled after restart. Provider HTTP acceptance is not proof of recipient receipt. Messages include source names and timestamps, not snapshots or URLs. Download complete configuration instructions.

Install Studio locally

Runtime SHA-256 checksums. The website package contains runtime files and documentation; the developer test suite is separate.

Requires Node.js 22 or newer. Download the ZIP and extract every file into a dedicated directory. Open a terminal there and run:

node studio.mjs

Open http://127.0.0.1:4321/ on that computer. Ctrl+C stops the application.

Add an authorized public source and run its first check to establish the baseline. Start monitoring to enable scheduled checks. Monitoring starts paused after restart. Data is local and unencrypted; Studio does not import previous CLI snapshots. Do not expose the local server to the internet.

03 / CLI alternative

Run the command-line edition.

Download CLI engineExample configuration

Requires Node.js 22. Save both files together, then run the following command from that folder.

node signal-desk.mjs sources.json signal-data --once

Remove --once for scheduled operation. Ctrl+C stops the process.

The supplied example monitors the Bot.AutoHustle release field every 15 minutes. Use direct HTTP(S) URLs that you own or have permission to poll. Redirects, credentials, URL queries and fragments are rejected.

Illustrative output / not live data
{"id":"bot-release","kind":"changed",
 "before":"0.9.0","after":"0.10.0"}
  • 1–20 sources, 5 minutes to 24 hours between scheduled checks.
  • Text or JSON, optional JSON Pointer for a specific field.
  • 512 KiB response limit and 10-second request timeout.
  • Local state file containing the latest normalized snapshots and up to 200 events.

Do not use sensitive sources: snapshots and console output are unencrypted. HTML is compared as raw text; there is no browser rendering or semantic AI analysis. The 0.1 CLI edition has no alerts or graphical interface; Studio 0.4 is the separate graphical evaluation.
